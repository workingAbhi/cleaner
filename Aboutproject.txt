# 1. PROJECT OVERVIEW

Project name:

**Cleaner**

Cleaner is an **Inspection & Compliance Platform**.

It is NOT simply an AI washroom monitoring application.

The core product allows users associated with a specific outlet/RO (Retail Outlet) to perform inspections, capture photos for individual inspection items, submit/retain inspection results, and later allow administrators to view inspection/compliance information.

AI is one component of the overall platform and will be integrated later.

For now, the priority is:

1. Build the mobile UI.
2. Build clean application architecture.
3. Use mock/local APIs.
4. Make the frontend independent of the eventual backend.
5. Make backend integration easy later.

# 17. IMPORTANT ASYNC RULE

All AsyncStorage/database operations are asynchronous.

Always use:

```ts
await
```

when calling:

* getInspectionUploads
* findInspectionUpload
* addInspectionUpload
* updateInspectionUpload
* deleteInspectionUpload

Do NOT accidentally treat async functions as synchronous.

For example, this is WRONG:

```ts
const existing = getInspectionUploads(roId).find(...);
```

Correct:

```ts
const uploads = await getInspectionUploads(roId);

const existing = uploads.find(...);
```

Likewise:

```ts
const existing = await findInspectionUpload(id);
```

and:

```ts
await addInspectionUpload(upload);
```

This was previously a source of runtime issues, so be careful when modifying this layer.

# 25. DELETE BEHAVIOR

Delete is a **soft delete**.

Do NOT physically remove the record from storage.

Instead:

```ts
deletedAt
```

is populated.

And:

```ts
editingHistory
```

gets a:

```ts
DELETED
```

entry.

Normal GET operations filter out deleted images.

This preserves audit history.
